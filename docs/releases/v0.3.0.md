# Кладовка v0.3.0

Панель управления файлами, защищённый служебный API и исправления хранения/репликации.

## Изменения

- В панели: поиск полок, загрузка файлов с префиксом, скачивание, удаление файлов и пустых полок, постраничный список объектов.
- Реальные показатели файловой системы, локальная статистика и счётчики трафика.
- Basic-авторизация панели, JSON API, метрик и состояния кластера; Bearer-токен для всех внутренних маршрутов.
- Исправлены SigV4 при `?uploads`, пересылка подписанных запросов на primary, Range-чтение, удаление вложенных объектов и граница пагинации.
- Загрузки обычных объектов используют временные файлы вместо полного буфера RAM; проверяются лимиты и SHA-256 подписанного содержимого.
- Multipart направляется на primary, проверяет ключ/части/ETag/полный размер и копирует результат на реплики. При сбое копирования можно повторить завершение с тем же UploadId.
- Ошибки репликации PUT/DELETE возвращаются клиенту; создание и удаление полок передаются пирам.
- Проверка конфигурации и корректная остановка сервера с ожиданием запросов до 30 секунд.
- Обновлены инструкции администратора и пользователя, Prometheus-конфигурация и CI.

## Обновление с v0.2.0

**Изменилось управление доступом.** Проверьте интеграции до замены бинарника:

1. Сделайте резервную копию DATA_ROOT и конфигурации. Прекратите записи и остановите службу.
2. Сохраните прежние ACCESS_KEY/SECRET_KEY или согласованно обновите их у клиентов. Стандартные тестовые ключи замените.
3. Панель `/ui/`, `/api/*`, `/metrics` и `/cluster` теперь требуют HTTP Basic: ACCESS_KEY как пользователь, SECRET_KEY как пароль. S3 по-прежнему использует SigV4.
4. Задайте одинаковый случайный CLUSTER_TOKEN на всех узлах. `/internal/*` требует Bearer-токен. Без явного токена он выводится из SECRET_KEY.
5. В кластере NODE_ID должен совпадать с host:port в NODE_URL. RF не должен превышать число настроенных узлов. Состав кластера сохраняйте.
6. Обновите все узлы в согласованное окно обслуживания: смешанный кластер v0.2.0/v0.3.0 не является поддерживаемым режимом. Обновите Basic/Bearer-реквизиты Prometheus.
7. После запуска проверьте вход, PUT/GET, multipart и копии объектов. При 503 операция могла выполниться частично; повторите её после восстановления связи.

Формат каталогов данных сохраняется; отдельной миграции формата не требуется. Это не отменяет резервного копирования и проверки на копии данных. Для AWS CLI рекомендуются `AWS_REQUEST_CHECKSUM_CALCULATION=when_required`, `AWS_RESPONSE_CHECKSUM_VALIDATION=when_required` и path-style addressing.

## Сборки и проверка

Вложения: Linux amd64, arm64, armv7, armv6 и удобные имена для Raspberry Pi 32/64-bit. `SHA256SUMS` содержит SHA-256 каждого бинарника. Скачайте подходящий файл, сравните его `sha256sum` с записью в SHA256SUMS и установите право исполнения. Встроенная версия: `kladovka -version`.

Для сборки из исходников требуется Go 1.25+. Проверки: `go test -race ./...`, `go vet ./...`, кросс-сборки Linux; также проверены AWS CLI и два локальных узла.
