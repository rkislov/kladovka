# Кладовка v0.4.0

Выпуск добавляет восстановление реплик и автоматический failover в отдельном consensus-режиме, управляемое изменение состава, светлую панель, разграничение доступа и эксплуатационный мониторинг.

## Возможности

- Светлая адаптивная панель на Tailwind CSS, загрузки и действия с объектами, квоты и статистика.
- Журнал локальных записей/удалений, SHA-256, восстановление после сбоя, квоты, ограничения временных загрузок и TTL multipart.
- Пользователи S3 с несколькими ключами, роли на полки, отзыв ключей без перезапуска. Отдельный администратор панели, сеансы, CSRF и JSONL-аудит.
- Consensus на Raft/BoltDB: журнал и снимки с данными, общий каталог, подтверждение большинством, выбор лидера, догоняющая репликация и восстановление повреждённых блоков. Без большинства чтение и запись отклоняются.
- Замена потерянного участника через новую инкарнацию и проверенного Nonvoter. Добавление/вывод в пределах 3–5 участников, передача лидерства и продолжение сохранённой операции после рестарта.
- Метрики диска, Raft, восстановления и операций состава. Десять правил Prometheus с promtool-тестами и руководством подключения Alertmanager.

## Установка и обновление

Выберите бинарник для своей платформы и проверьте SHA256SUMS. Для consensus нужны Linux amd64 или arm64 и отдельный DATA_ROOT каждого участника. ARMv6/v7 поддерживают legacy.

Сохраните резервную копию всего DATA_ROOT вместе со скрытыми каталогами, конфигурацией, политиками и сертификатами. Для обновления согласуйте окно без записей, замените бинарник и проверьте данные по SHA-256. Не удаляйте журнал и не меняйте дисковую идентичность при обновлении.

Legacy остаётся режимом по умолчанию. Переход к consensus требует нового пустого кластера и контролируемой миграции. Старые legacy-каталоги не импортируются автоматически. Первоначальная группа consensus содержит 3 или 5 узлов, RF=N. Изменение состава выполняется через административный API, а не правкой исходных RAFT_PEERS/RF.

## Проверки и границы

Race-тесты, vet, AWS CLI, проверка резервного восстановления, пяти­процессный сценарий consensus и promtool входят в CI. Проверены отказ лидера, возврат узла, замена потерянного диска, изменение состава и полный рестарт.

Для consensus по-прежнему нужен аппаратный и нагрузочный пилот. RPO/RTO и SLA не заявлены. RF<N, witness и группы больше пяти не поддерживаются. Незавершённые multipart-части не реплицируются как готовые объекты. Отмена/переназначение ожидающей операции состава при утрате диска кандидата не реализованы. Нет корзины, версий объектов и полной совместимости со всеми API Amazon S3. Политики доступа требуют отдельной доставки, уведомления — настройки Alertmanager.
